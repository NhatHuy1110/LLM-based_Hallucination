# Mitigating Hallucination in LLM-based Question Answering via Evidence Grounding and Self-Verification
*A lightweight empirical study on SQuAD 2.0 (answerable + unanswerable QA) using training-free prompting protocols.*

## Overview
Large Language Models (LLMs) can produce fluent yet **unsupported** answers—commonly referred to as *hallucinations*—especially when questions are unanswerable or the model is uncertain. This repository provides a **small-scale, reproducible** evaluation pipeline that compares three prompting conditions:

- **A — No Context (Baseline):** question-only QA.
- **B — Evidence Grounding:** answer using *only* the provided passage; otherwise output **"Not enough information"**.
- **C — Evidence Grounding + Self-Verification:** answer using only the passage, **quote supporting sentence(s)**, and abstain if unsupported.

The goal is to quantify the **reliability–coverage trade-off** (hallucination reduction vs. abstention) in a controlled setting.

---

## Method Summary
### Dataset
- Source: **SQuAD 2.0** development split (contains *answerable* and *unanswerable* questions).
- Subset: **100** examples sampled as **60 answerable / 40 unanswerable**.
- Evidence passage is truncated to **800 characters** to control prompt length.

### Model and Inference
- Model: `llama-3.3-70b-versatile` (queried via **Groq API**).
- Generation (default): `temperature=0.7`, `top_p=0.95`, `max_tokens=500`.

### Evaluation Protocol
Manual binary annotation (per example, per condition):
- **Correctness (0/1):**  
  - answerable: matches gold answer (minor formatting differences allowed)  
  - unanswerable: correctly abstains with `"Not enough information"`
- **Hallucination (0/1):** unsupported content  
  - for B/C: claims not supported by the passage  
  - for A: incorrect/guessed answers (esp. on unanswerable)
- **Abstention (0/1):** outputs the canonical refusal string
- **Citation Faithfulness (C only, 0/1):** quoted sentence(s) truly support the answer

---

## Key Results (SQuAD 2.0 subset, N=100)
| Metric | A: No Context | B: Evidence | C: Evidence + Verify |
|---|---:|---:|---:|
| Correctness (%) | 23 | 81 | 86 |
| Hallucination (%) | 77 | 4 | 0 |
| Abstention (%) | 0 | 42 | 39 |
| Citation faithfulness (%) | — | — | 100 |

**Main takeaway:** evidence grounding is the largest contributor to hallucination reduction, and self-verification acts as an additional guardrail—at the cost of increased abstention (reduced coverage).

## Repository Structure
- `main.py` — entry point (run experiments and/or analysis)
- `prepare_squad_dataset.py` — prepares the 100-sample SQuAD 2.0 subset (60/40) and truncates passages
- `experiment.py` — runs inference for conditions A/B/C and saves outputs
- `prompts.py` — prompt templates for conditions A/B/C
- `llm_api.py` — Groq API wrapper (OpenAI-compatible chat completions style)
- `evaluation.py` — evaluation templates and parsing helpers for manual scoring
- `analysis.py` — aggregates metrics and generates plots
- `config.py` — configuration (model name, sampling params, paths)
- `analysis_report_squad.md` — example analysis output / summary (generated)
- `requirements.txt` — Python dependencies

## Setup

### 1) Create a virtual environment (recommended)
```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
```

### 2) Install dependencies
```bash
pip install -r requirements.txt
```

### 3) Configure API credentials
This project uses the **Groq API**. Export your key as an environment variable (recommended).

**Windows (PowerShell):**
```powershell
setx GROQ_API_KEY "YOUR_KEY_HERE"
```

**macOS/Linux:**
```bash
export GROQ_API_KEY="YOUR_KEY_HERE"
```

> If your code uses a different variable name, update it accordingly in `llm_api.py`.

## Reproducibility: How to Run

### Step A — Prepare the dataset
```bash
python prepare_squad_dataset.py
```

This generates a small JSON dataset containing:
- `question`, `context` (truncated), `is_impossible` (unanswerable), and gold answers where available.

### Step B — Run the QA experiments (A/B/C)
```bash
python main.py
```

This runs the three prompting conditions and saves model outputs for later scoring.

### Step C — Manual scoring
Follow the template generated by `evaluation.py` (or your evaluation markdown/CSV workflow) and label:
- correctness, hallucination, abstention (and citation faithfulness for condition C)

### Step D — Aggregate results and plot
```bash
python analysis.py
```

This produces summary metrics and a comparison plot (e.g., `results_comparison_squad.png` if enabled).

## Prompting Conditions (High-level)
- **A — No Context:** `Answer the question concisely.`
- **B — Evidence-grounded:** `Use ONLY the passage. If insufficient, output: Not enough information.`
- **C — Evidence + Verify:** `Answer using ONLY passage, quote supporting sentence(s), and abstain if unsupported.`

See `prompts.py` for exact prompt templates.

---

## Notes on Interpretation
- The evaluation uses **gold contexts** from SQuAD 2.0 (no retrieval). Results therefore isolate *generation faithfulness* rather than retrieval quality.
- Increased abstention is expected and reflects a **coverage–reliability trade-off**: safer systems may refuse more often.

---

## Limitations
- Small sample size (N=100) and **manual** labeling (potential subjectivity).
- Single model configuration and single dataset (limited generalization).
- Passage truncation may remove evidence and increase abstentions.
